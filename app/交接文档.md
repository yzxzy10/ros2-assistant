## 2. 三步跑起来（本地验证用）

```bash
# 1. 解压后进入目录
cd ROS2学习助手-v1.18.0-可运行

# 2. 配 Key（Windows 下注意文件名前面有个点）
copy .env.example .env
# 编辑 .env，把 DASHSCOPE_API_KEY 填成真实值（阿里云百炼控制台申请）

# 3. 启动
python -X utf8 server.py
#   浏览器打开 http://127.0.0.1:8000/
```

**自检三条命令**（确认环境没问题）：

```bash
curl -s http://127.0.0.1:8000/api/health     # 应返回 ok:true + app_version:1.18.0
curl -s http://127.0.0.1:8000/api/meta       # 应返回 31 个 deb 的包池信息
curl -s http://127.0.0.1:8000/api/auth/me    # 应返回 loggedIn:false（未登录）
```

**本机环境已确认的事实**（不要再重复排查）：

- 本机**没有 Docker**、**没有 ROS2/colcon** → 本地 `sandbox.status()` 返回
  `{available: false, backend: "none", reason: "本机既没有 Docker 也没有 colcon/ros2"}`
  → **本地点"编译运行"会提示不可用**，这是正常的，不是 bug。
- **线上沙箱有 Docker**（`backend=docker`，镜像 `ros:jazzy-ros-base`），真编译在线上是通的（实测 34.7 秒跑通四节点链路）。

## 5. 系统架构

### 5.1 请求主链路

```
浏览器 (public/)
   │  POST /api/chat/stream  ← SSE 流式，token 级推送
   ▼
server.py  (ThreadingHTTPServer，一个文件管全部路由)
   │  ① 身份：identity（签名 Cookie）→ 登录后换成账号 uid（accounts）
   │  ② 限流：ratelimit（按 uid / IP）
   │  ③ 分发：/api/chat* → orchestrator；/api/graph* → graph_api；
   │           /api/project/import* → project_import；/api/model/* → model_scene
   ▼
orchestrator（大脑，串起全部 Agent）
   ├─ 意图识别（项目需求 / 单点提问 / 仿真建模 / 继续上次）
   ├─ 教学流水线：wf_need → wf_plan → wf_code（每个阶段是一个 Agent + 一套提示词）
   ├─ 仿真流水线：wf_sim → model_inspect（体检）→ sim_build（生成 URDF）
   ├─ 检索：kb（知识库）→ prompts（按角色取提示词）
   └─ 落盘：store（会话状态 state.json）/ archive（30 天归档）
   ▼
llm.py → 阿里云百炼（OpenAI 兼容接口）
```

### 5.2 三条"看得见"的能力链路

| 能力 | 后端链路 | 前端位置 |
|---|---|---|
| **架构图（通信拓扑）** | `graph.py`（AST 解析 rclpy 节点，不是正则）→ `graph_api.py`（读/改/提交） | `graph.js` 左栏画布 |
| **链路验证（真编译 + 逐跳取证）** | `chain_*` 11 个模块：`chain_plan`（规划）→ `chain_script`（生成验证脚本）→ `chain_exec`（Docker/colcon 编译）→ `chain_run`（启动各节点）→ `chain_probe`（逐跳订阅取证）→ `chain_diag`（诊断）→ `chain_verify`（汇总 SSE 推送） | 画布上「编译运行」按钮 + 结果条 |
| **3D 模型预览** | `model_scene.py`（解析 URDF/xacro → 场景 JSON + 内联 mesh）→ `/api/model/<sid>` | `viewer_babylon.js`（Babylon.js PBR） |

### 5.3 依赖方向（改代码前必看）

```
server.py
  └── app/{orchestrator, graph_api, project_import, model_scene, accounts, sandbox, chain_verify, pkgcache}
        └── app/{agents, prompts, llm, kb, store, archive, versions, config, env, paths, identity, auth, ratelimit, progress}
              └── 标准库（无第三方）
```

**没有第三方包依赖**——这是刻意的设计（评委/学校机器上不装环境也能跑）。新增依赖前请三思。

## 6. 模块逐个说明（51 个）

### 6.1 基础设施（改配置先看这几个）

| 模块 | 作用 | 注意 |
|---|---|---|
| `versions.py` | **版本单一事实来源**：`APP_VERSION`、ROS 发行版元数据（jazzy/humble） | 改版本只改这里；文档/界面/健康检查都从这里取值 |
| `config.py` | 读 `config.json`（模型名、温度、编译参数、知识库参数） | 结构见第 8 节 |
| `env.py` | 读 `.env`（手写解析，无 dotenv 依赖） | 支持注释、引号、`export` 前缀 |
| `paths.py` | 可变数据目录统一入口（sessions/data/archive），支持 `ROS2_DATA_DIR` 挂载卷 | 所有落盘都必须走这里，别自己拼路径 |
| `identity.py` | 匿名身份：服务端签名的 Cookie（HMAC），**前端自报 uid 会被忽略** | 跨部署稳定需显式设 `ROS2_ID_SECRET` |
| `auth.py` | 接口访问控制：令牌 + IP 白名单 | 与 `accounts.py` 是**两回事**，别混 |
| `accounts.py` | 账号体系：用户名+密码，PBKDF2-HMAC-SHA256（20 万轮）+ 每账号盐 | 登录后 uid 换成 `acct_<hash>`，数据跟着账号走 |
| `ratelimit.py` | 限流（按 uid/IP，进程内滑动窗口） | 公网分享务必打开 |
| `progress.py` | 任务进度事件（前端那串"在做哪一步"） | 新增阶段统一用 `progress.step()` |
| `store.py` | 会话读写（`sessions/<sid>/state.json`） | 有 `reassign`（会话迁移到账号） |
| `archive.py` | 30 天未活动会话归档为 zip | |
| `llm.py` | 大模型调用（OpenAI 兼容 /chat/completions，流式） | 超时/重试/降级都在这里 |

### 6.2 教学与编排

| 模块 | 作用 |
|---|---|
| `orchestrator.py` | **核心大脑（2000+ 行）**：意图路由、教学流水线、仿真流水线、模型体检/修控制器的交互 |
| `agents.py` | Agent 注册表（11 个：需求分析、架构师、节点规格、代码工程、教师、答疑、模型工程师、仿真工程师…） |
| `prompts.py` | 全部提示词（含 `SYS_SIM_SPEC` 仿真规格提示词） |
| `wf_need.py` / `wf_plan.py` / `wf_code.py` | 三阶段工作流：需求澄清 → 节点规划 → 代码生成/修复 |
| `wf_sim.py` | 仿真建模工作流（URDF + ros2_control + gazebo 插件） |
| `checker_requirement.py` / `checker_code.py` | 产出质量闸门（不达标就重来） |
| `kb.py` | 知识库检索（`kb_data/` 关键词 + 打分） |
| `vision.py` | 截图理解（多模态，qwen-vl-max） |

### 6.3 架构图

| 模块 | 作用 |
|---|---|
| `graph.py` | **AST 解析**（不是正则）：找 `create_publisher/subscription/service`，推断话题、类型、方向 |
| `graph_api.py` | 图的读/改/提交：改话题名会同步改代码里的字符串；提交后生成真正的 ROS2 包 |

### 6.4 链路验证（压缩包带来的 chain 架构）

| 模块 | 作用 |
|---|---|
| `chain_plan.py` | 从图推出"验证计划"：节点顺序、要注入的话题、期望跳数 |
| `chain_script.py` | 生成验证脚本（启动节点 + 逐跳探针） |
| `chain_exec.py` | 编译执行：**Docker（ros:jazzy-ros-base）或本机 colcon**，二选一自动探测；`fallback_mock` 可退化模拟 |
| `chain_run.py` | 运行编排（起节点、等 boot、超时控制） |
| `chain_probe.py` | 逐跳取证：给每条边发测试消息，看对端是否真的收到 |
| `chain_msg.py` | 消息类型构造（按 ROS 类型填默认字段） |
| `chain_flow.py` / `chain_diag.py` | 数据流分析与失败诊断（"第 2 跳没收到 → 话题名不匹配"这类结论） |
| `chain_verify.py` | 总控 + 快照（SSE 推送进度，前端三色标注节点/连线） |
| `sandbox.py` | 编译后端探测与状态（docker / colcon / none） |
| `base_pkgs.py` / `dep_scan.py` / `pkgcache.py` | 依赖扫描 + deb 包池（31 个包本地缓存，编译不依赖外网） |

## 7. 数据与存储

```
<数据根目录>/                       ← 默认 = 项目根目录；可用 ROS2_DATA_DIR 指向挂载卷
├── sessions/<sid>/state.json       ← 会话状态（消息、阶段、待选项、导入项目）
├── sessions/<sid>/ros2_ws/src/...  ← 生成/导入的代码（固定落这里，不写用户原工程）
├── data/profile.db                 ← 学习画像（SQLite，表 profiles）
├── data/accounts.db                ← 账号（SQLite，表 accounts；首次注册时创建）
├── data/.id_secret                 ← 身份签名密钥（未设 ROS2_ID_SECRET 时自动生成）
└── archive/<sid>.zip               ← 30 天未活动会话归档
```

**迁移用户数据**：把整个数据根目录一起拷走即可（`data/profile.db` + `data/accounts.db` + `sessions/`）。
**本包里不含运行时数据**——当前 `_live/data` 只有一个空画像、`sessions` 只有一个诊断用会话，`accounts.db` 还不存在（账号都注册在线上那台），所以没有用户数据需要迁移。

## 8. 配置项

### 8.1 `config.json`（关键段）

```json
{
  "models": { "chat": "qwen-max", "coder": "qwen3-coder-flash", "vision": "qwen-vl-max", ... },
  "ros": {
    "distro": "jazzy",
    "verify": {                    // ← 链路验证总开关，踩过坑，别乱改
      "enabled": true,             //   false = 整个"编译运行"消失
      "backend": "auto",           //   auto → 有 docker 用 docker，有 colcon 用 colcon
      "fallback_mock": false,      //   true = 没真环境时退化模拟（会产生"假通过"，慎用）
      "memory": "6g", "cpus": "3", "build_jobs": "1", "pkg_jobs": "1",
      "timeout_build_sec": 300, "timeout_run_sec": 25, "fix_rounds": 1
    },
    "chain_verify": {
      "hop_timeout_sec": 12,       // 每跳等消息的时间
      "boot_wait_sec": 8,          // 节点启动等待
      "build_timeout_sec": 3600,
      "total_timeout_sec": 120,
      "inject_rate": 5
    }
  }
}
```

### 8.2 `.env`（全部可选，除 Key 外）

| 变量 | 默认 | 说明 |
|---|---|---|
| `DASHSCOPE_API_KEY` | 无 | **必填**，阿里云百炼 |
| `PORT` | 8000 | 监听端口 |
| `ROS2_AUTH_TOKEN` | 空 | 空=公开；填了=要令牌；`tokenA:u_alice,tokenB:u_bob`=绑定 uid |
| `ROS2_RATE_CHAT_PER_MIN` / `ROS2_RATE_API_PER_MIN` | 20 / 120 | 限流 |
| `ROS2_DAILY_CHAT_MAX` | 2000 | 全站日对话上限（保险丝） |
| `ROS2_ALLOW_IPS` | 空 | IP/CIDR 白名单 |
| `ROS2_TRUST_PROXY` | 空 | 反代后读真实 IP |
| `ROS2_ID_SECRET` | 自动生成 | 身份签名密钥（多实例必须一致） |
| `ROS2_DATA_DIR` | 项目根 | 数据目录 |
| `ROS2_COOKIE_SECURE` | 空 | HTTPS 下带 Secure |

## 12. 六条踩坑经验（血泪，务必读）

1. **合并/升级时，配置文件必须三方对比。**
   曾经只比"本地 vs 部署目录"（两个都是旧的），漏了跟新版压缩包比 → `config.json` 的
   `verify.enabled` 还是 `false` → 「编译运行」整个功能消失，用户以为项目跑不通。
   **三方 = 新版 / 本地 / 部署目录。**

2. **机器人模型"显示成方块"，先按顺序查三件事**：
   ① 导入白名单有没有 `.dae/.stl/.obj`（没有 → 网格在导入时就被丢了，这是最常见的根因）；
   ② 前端解析器支不支持该格式（原前端只认二进制 STL，DAE 一律退化成 3cm 方块）；
   ③ mesh 大小上限（真实 CAD 单个部件常 1–2MB，原上限 1.2MB 全部被跳过）。

3. **mesh「找不到」比「解析不了」更常见。**
   URDF 写 `package://pkg/meshes/x.dae`，真实文件可能在 `pkg/panda/meshes/x.dae`（多一层）。
   不能只按标准路径拼一次，必须**容错回溯**（按文件名 + 路径后缀索引）。

4. **真实 description 包普遍是多文件的。**
   `xacro:include` 拆成 base/arm/gripper，只解析单个文件就只能画出一个部件（"只修了一半"的假象）。
   展开 include 时**必须剥掉被包含文件的 `<?xml?>` 和 `<robot>` 包装**，否则拼出多根标签的非法 XML，整份解析失败。

5. **模板要过滤。** 同时展开"已生成的 urdf"和"宏定义 xacro"，会收进一批
   `${prefix_arm}${link0_name}` 这种模板名 link（panda 28 个 link 里 11 个是幽灵）。
   含 `${` / `$(` 的名字单独收，只有整个模型都是模板时才回退使用。

6. **CDN 是弱网杀手。** 3D 引擎曾走 CDN（未压缩 8.9MB），弱网要 15 秒，自检只等 9.8 秒 → 误报
   `FAIL 0/0`（其实模型能渲染）。现已把库内联进预览页，彻底离线。
