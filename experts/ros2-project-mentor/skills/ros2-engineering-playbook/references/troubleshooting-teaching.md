# ROS2 排障与教学参考

## 证据驱动的排障顺序

1. 固定环境：ROS2 发行版、Ubuntu/系统、工作空间、source 顺序、C++/Python、仿真或实机。
2. 固定现象：完整报错、期望行为、实际行为、复现命令、最近修改。
3. 缩小层次：依赖与构建 → 包/可执行安装 → 节点启动 → 通信端点 → 数据与 QoS → 时间/TF → 算法与执行器。
4. 提出有区分度的检查，每次优先验证一个假设。
5. 做最小修复并给出复验方法；没有证据时写“可能原因”，不伪装确定结论。

## 高频问题对照

- `Package not found` / `No executable found`：包路径、构建是否成功、安装规则、entry point/target、当前终端是否 source install/setup。
- 找不到消息类型或接口链接失败：接口文件是否列入生成配置、依赖是否声明、接口包是否先构建、导入/头文件是否正确。
- 订阅无数据：发布者与订阅者是否都运行、实际名称与命名空间、类型、QoS、DDS 网络和回调是否进入事件循环。
- 回调不触发或节点卡死：spin/executor、阻塞等待、耗时处理、多线程与回调组是否匹配。
- 定时/坐标异常：仿真时间、消息 stamp、frame_id、TF 发布者、静态/动态变换及外推时间。
- Gazebo 无传感器/不运动：插件与模型加载、话题重映射、控制器配置、`/clock`、use_sim_time、机器人描述和关节名称。
- Nav2 不规划/不移动：map/odom/base_link 链、定位、代价地图、传感器、控制器和速度指令链路逐项检查。
- MoveIt 2 规划失败： planning group、机器人描述/语义描述、关节状态、当前状态、目标约束、碰撞和规划器配置。

## 常用诊断命令

```bash
ros2 node list
ros2 node info /<node_name>
ros2 topic list -t
ros2 topic info /<topic> -v
ros2 topic echo /<topic>
ros2 topic hz /<topic>
ros2 interface show <package>/<kind>/<Type>
ros2 service list -t
ros2 action list -t
ros2 param dump /<node_name>
ros2 run tf2_tools view_frames
```

仅执行与当前问题有关的命令；不要以收集信息为由要求用户运行全部命令。

## 安全边界

- 实机前先仿真，初始低速并设置速度/关节限幅、通信超时和停止策略。
- 涉及运动控制时说明急停和清空障碍物等现场条件，不代替用户进行未授权硬件动作。
- 仿真成功不等于实机安全或性能达标。

## 教学结构

### 入门

用最短完整示例讲清节点骨架、通信对象、回调和 init/spin/shutdown；以可观察现象验证，而不是先讲所有底层概念。

### 进阶

结合当前项目解释 QoS、参数、launch、自定义接口、TF、回调并发与包边界，安排小步修改练习。

### 综合

围绕感知—定位—规划—控制链路，解释接口契约、时间坐标、错误传播、性能与验收，引导学习者读日志和计算图。

每次代码教学优先包含：

1. 核心思路与箭头数据流。
2. 当前代码实际使用的 API 和消息字段。
3. 2–3 个易错点，每个含现象、原因、解决。
4. 一个可在原代码上完成的拓展练习。
5. 对应构建运行与验证现象。

不照抄无关知识库内容，不在教学中重复大段完整代码。
